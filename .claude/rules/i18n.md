# Translations

- Every user-facing string (UI, emails, push, SMS, error messages) is a key in
  `packages/i18n/messages/<locale>.json`. No literals in components, templates or
  services, including `aria-label`, `alt`, placeholders and page titles.
- Every key goes into every catalog (`en.json` and `es.json` today) at the same path, in
  the same change. `src/index.ts` makes a missing key a type error, and
  `src/index.test.ts` checks that every error code, audit event, notification category,
  in-app notification and webhook event has its keys.
- Messages are ICU: `{count, plural, one {# item} other {# items}}`, `{name}`. Never
  build a sentence by concatenating translated fragments; pass values as arguments.
- Arguments are type-checked on web, mobile and servers: `bun run gen` types English
  with each message's text (`messages/en.d.json.ts`), so a missing argument or a number
  passed to a plain `{name}` fails to compile. A number takes `{name, number}` (it's
  formatted for the reader's locale too). A test fails when a translation names other
  arguments than English. For a key known only at run time (an error code, a
  notification type), `loosely(t)(key, params)` from `@repo/i18n`; nowhere else.
- Namespaces are the top-level keys (`auth`, `settings`, `email`, `notification`,
  `errors`, `mobile`, ...). Put a key next to its siblings; reuse `common.*` for shared
  words like Save and Cancel instead of duplicating them.
- Dates, numbers and money: `useFormatter()` / `getFormatter()` (locale and time zone
  come from the provider), never `toLocaleString` or `Intl.*` with a hard-coded locale.
- A new language: copy `en.json` to `<code>.json`, add the code to `locales` and
  `catalogs` in `src/index.ts`, and to `RTL` in `apps/web/src/app/layout.tsx` if it is
  right-to-left.
- Mobile keys are not type-checked the way web keys are; double-check the path exists.
